# وضعیت فرانت فاز یک کی کلاب

تاریخ بررسی: ۲ آبان ۱۴۰۵ (آخرین کامیت: `4de148f`)

## آماده است

| بخش | صفحه‌ها و فایل‌ها |
|---|---|
| سایت عمومی | صفحه‌ی اصلی، انتخاب رشته (`/sport`)، رزرو (`/book/[sport]`)، پرداخت (`/checkout`)، برگشت از بانک (`/payment/return`)، مربیان (`/coaches`)، ورود (`/login`)، صفحه‌ی ۴۰۴ |
| پنل بازیکن | داشبورد، رزروهای من، کیف پول، اعلان‌ها، تیکت‌ها، پشتیبانی فنی، پروفایل و رمز |
| پنل منشی | داشبورد، جدول رزروها، رزرو جدید، کاربران، کیف پول و تراکنش‌ها، گزارش صندوق، مربیان، گالری و رسانه (طبق دسترسی) |
| پنل ادمین | داشبورد، گزارش مالی، زمین‌ها، بستن زمین، قیمت‌گذاری، تنظیمات، کارکنان و دسترسی‌ها، مربیان، گالری و رسانه، تاریخچه‌ی تغییرات، به‌علاوه‌ی صفحه‌های مشترک با منشی |
| قوانین و خطا | `/terms` و `/privacy` (متن پیش‌نویس در `src/config/legal.ts`، قوانین لغو زنده از تنظیمات ادمین) با لینک در فوتر، ورود و پرداخت؛ صفحه‌ی خطا برای سایت، پنل و کل برنامه |
| شلوغی رزرو | تلاش دوباره بعد از `429` با `Retry-After`، کلید یکتا برای پرداخت (رزرو دوباره ثبت نمی‌شود)، شمارش معکوس باز شدن روز جدید روی صفحه‌ی رزرو، هشدار و جلوگیری از رد شدن از سقف رزرو فعال |
| SEO و GEO | آدرس canonical و توضیح هر صفحه، noindex برای صفحه‌های شخصی، `robots.txt` (با اجازه‌ی صریح به خزنده‌های هوش مصنوعی)، `sitemap.xml`، تصویر اشتراک‌گذاری، داده‌ی ساختاریافته (باشگاه، سایت، سؤالات متداول، خدمات با قیمت، مسیر صفحه، مربیان)، `/llms.txt`، یک h1 در هر صفحه |
| زیرساخت | همه‌ی داده‌ها از `src/engine/api.ts` (هیچ صفحه‌ای از داده‌ی نمونه نمی‌خواند)، امنیت فرانت (`docs/security.md`)، قرارداد API برای بک‌اند (`docs/api-contract.md`)، موتور مشترک با نور کلاب (`src/engine`) |

## مانده‌ها

### ۱. منتظر دیگران (کار فرانت تمام است یا آماده‌ی شروع)

| مورد | منتظر چه کسی | توضیح |
|---|---|---|
| اتصال به بک‌اند | تیم بک‌اند (Swagger) | همه‌ی endpointها در `docs/api-contract.md` هستند. با رسیدن Swagger فقط `api.ts` و `http.ts` تطبیق داده می‌شوند و بعد همه‌ی جریان‌ها با داده‌ی واقعی تست می‌شوند. |
| تایم ثابت و برنامه‌ی مربی‌ها | کارفرما (چک‌لیست تایم ثابت) | بعد از پاسخ چک‌لیست: فرم درخواست تایم ثابت برای بازیکن، مدیریت تایم‌های ثابت برای منشی و ادمین، و بازه‌ی رزرو عمومی. |
| اطلاعات تماس باشگاه | کارفرما | آدرس، تلفن، لینک نقشه و مختصات نقشه (`geo`) در `src/config/content.ts` خالی هستند؛ برای جستجوی محلی («پدل نزدیک من») و پاسخ هوش مصنوعی مهم‌اند. |
| آدرس دامنه | تیم سرور | `NEXT_PUBLIC_SITE_URL` در production تنظیم شود؛ بعد سایت در Google Search Console و Bing Webmaster ثبت و `sitemap.xml` معرفی شود. |
| عکس‌ها و محتوای واقعی | کارفرما یا منشی | عکس‌های گالری، عکس و اطلاعات واقعی مربی‌ها (از پنل)، ویدیوها و عکس‌های صفحه‌ی اصلی در صورت نیاز. |
| تأیید متن قوانین و حریم خصوصی | کارفرما | پیش‌نویس در `src/config/legal.ts` آماده است؛ بعد از تأیید، `LEGAL_DRAFT` را `false` کنید. |

### ۲. کارهای فرانتی که مانده

| مورد | اهمیت | توضیح |
|---|---|---|
| ثبت نظر بازیکن | متوسط | بخش نظرها فقط می‌خواند؛ فرم ثبت نظر بعد از بازی و تأیید نظر در پنل نیست. |
| لایه‌ی ردیابی کاربر (`track`) | متوسط | پیشنهاد شده ولی ساخته نشده؛ مستقل از ابزار (PostHog یا Umami روی سرور خودتان). |
| بررسی حالت تیره و موبایل | متوسط | صفحه‌های جدید (پنل منشی و ادمین، مربیان، گالری، پشتیبانی) در حالت تیره و موبایل کامل بررسی نشده‌اند. |
| بررسی دسترس‌پذیری | متوسط | ممیزی کامل (صفحه‌کلید، صفحه‌خوان، کنتراست) انجام نشده است. |
| بهینه‌سازی ویدیوها | پایین | ویدیوهای بالای صفحه ۱.۶ تا ۳.۴ مگابایت‌اند؛ نسخه‌ی سبک‌تر برای موبایل و سرو از CDN بهتر است. |

### انجام‌شده بعد از این گزارش

- build تولیدی بدون خطا.
- تست end-to-end با Playwright در `tests/e2e`: ورود (کد پیامکی، شماره‌ی نامعتبر، ساخت حساب، محافظت پنل، next خارجی)، رزرو (مهمان تا ورود و برگشت، انتخاب و حذف زمین، پرداخت و کد رهگیری) و برگشت از درگاه (موفق و ناموفق). اجرا: `npm run build && npm run test:e2e`.
- تست واحد برای منطق موتور (قیمت، بازگشت وجه، امنیت) هنوز نیست.

### ۳. فاز بعد (عمداً «به‌زودی»)

هم‌بازی، مسابقات، پکیج مربی و رزرو جلسه‌ی مربی، کافه، فروشگاه.
