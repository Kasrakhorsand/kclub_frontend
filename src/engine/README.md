# موتور مشترک (engine)

منطق رزرو باشگاه، **بدون هیچ ظاهری**: نه کامپوننت، نه CSS، نه متن برند. هر سایت (K Club، نور کلاب، …) این پوشه را برمی‌دارد و ظاهر خودش را کاملاً جدا روی آن می‌سازد. در نتیجه دو سایت فقط در منطق یکی‌اند و از بیرون هیچ شباهتی ندارند.

یک قانون ESLint جلوی قاطی شدن را می‌گیرد: هر فایل `src/engine` که چیزی از `@/ui`، `@/app`، `@/config/site`، `@/config/home` یا یک فایل CSS import کند، خطا می‌دهد.

## چه چیزی داخلش است

| فایل | کار |
|---|---|
| `types.ts` | نوع‌های دامنه: رشته، زمین، رزرو، کاربر، سبد، سانس، تراکنش، تیکت |
| `venue.ts` | خواندن `config/venue.ts`: ساعت‌ها، قیمت هر سانس، رشته و زمین با id، درصد بازگشت وجه در لغو |
| `format.ts` | اعداد فارسی، تومان، تاریخ شمسی، تبدیل ارقام فارسی به لاتین |
| `store.ts` | وضعیت ماندگار: کاربر، نقش، تم، سبد، مسیر بعد از ورود |
| `api.ts` | تنها راه رسیدن به داده؛ تا تنظیم `NEXT_PUBLIC_API_URL` داده‌ی نمونه می‌دهد |
| `mock.ts` | داده‌ی نمونه تا وقتی بک‌اند وصل شود |
| `EngineProvider.tsx` | کش داده (React Query) و اعمال تم روی `<html>` |

### هوک‌ها

| هوک | چه می‌دهد |
|---|---|
| `booking/useBookingFlow(sport, {game, date, hour})` | روزهای قابل رزرو با تعداد سانس خالی، سانس‌های روز، زمین‌ها، وضعیت هر زمین، انتخاب زمین با تکرار هفتگی |
| `booking/useCart()` | اقلام سبد با نام زمین، جمع کل، حذف، رفتن به پرداخت (مهمان‌ها اول به ورود) |
| `booking/useCheckout()` | روش پرداخت، امکان کیف پول، پرداخت، خطا، کد رهگیری؛ مهمان را به ورود می‌برد |
| `booking/useOpenSlots(limit)` | نزدیک‌ترین سانس‌های خالی امروز (یا فردا) در همه‌ی رشته‌ها |
| `auth/useOtpLogin()` | مراحل ورود: شماره → کد → (ثبت‌نام)؛ فرم‌ها، تایمر ارسال دوباره، خطاها |
| `panel/usePanelSession()` | منتظر ماندن برای نشست، هدایت مهمان به ورود، منوی نقش، بخش فعلی، شمارنده‌ها، تغییر نقش، خروج |
| `panel/stats` | آمار امروز، جدول یک روز، بازه‌ی ساعت‌های اطراف حالا، رزروهای بازیکن، سری درآمد به تفکیک رشته |
| `panel/menus` | بخش‌های پنل برای هر نقش، نام نقش‌ها، آدرس هر بخش |

هوک‌ها فقط داده و تابع برمی‌گردانند. پیام‌ها (مثل «۲ از ۴ هفته اضافه شد») را UI از روی نتیجه می‌سازد، چون لحن هر سایت فرق دارد.

## شروع یک سایت جدید (مثلاً نور کلاب)

1. یک پروژه‌ی Next.js بسازید با همان وابستگی‌ها: `@tanstack/react-query`، `zustand`، `react-hook-form`، `zod`، `@hookform/resolvers`، `date-fns-jalali`. مسیر `@/*` باید به `src/*` اشاره کند.
2. پوشه‌ی `src/engine` را همان‌طور کپی کنید. **دست نزنید**؛ اصلاحات موتور را در هر دو پروژه یکسان نگه دارید.
3. `src/config/venue.ts` را برای باشگاه جدید بنویسید: رشته‌ها و بازی‌ها، زمین‌ها با رنگ کف، قیمت‌ها، ساعت کاری، قوانین لغو. برای نور کلاب: تنیس (۴ زمین خاک رس) و پدل (۳ زمین، ۲ سرپوشیده).
4. `src/config/content.ts` را اگر لازم است بنویسید. `site.ts`، `home.tsx` و `theme.css` مال UI هستند و هر سایت شکل خودش را دارد.
5. کل UI را از صفر بسازید (`src/ui` یا هر ساختاری که می‌خواهید) و فقط از هوک‌های موتور استفاده کنید. از UI کی کلاب چیزی کپی نکنید.
6. در `layout.tsx` محتوا را داخل `EngineProvider` بگذارید.

### چیزی که موتور هنوز ندارد

بخش‌های مخصوص نور کلاب مثل مسابقات با شمارش معکوس، برنامه‌ی هفتگی، عضویت و رویداد خصوصی هنوز در موتور نیستند. اگر منطق مشترک دارند (مثلاً ثبت‌نام مسابقه از طریق API)، اول به `api.ts` و یک هوک جدید در موتور اضافه می‌شوند، بعد هر سایت UI خودش را برایش می‌سازد.
